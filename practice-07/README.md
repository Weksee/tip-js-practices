## 3. Компоненты и состояние
- `App.jsx` — владелец основного состояния (`tasks`, `filters`, `editingId`).
- `TaskForm.jsx` — хранит локальное состояние черновика и ошибок.
- `TaskList.jsx`, `TaskItem.jsx` — отображают отфильтрованный список.
- `TaskFilters.jsx` — управляемые поля фильтров.
- `TaskStats.jsx` — выводит общую статистику.

Данные передаются вниз через `props`, а действия (создание, удаление, редактирование, изменение статуса) — наверх через функции-колбэки.

## 4. Неизменяемые обновления
Все операции с массивами (`addTask`, `updateTask`, `toggleTask`, `removeTask`) создают новые массивы и новые объекты вместо мутации существующих. Это гарантирует, что React зафиксирует изменение и перерисует интерфейс.

## 7. Ответы на контрольные вопросы
1. **Чем JSX отличается от строки HTML?** JSX — это синтаксический сахар для `React.createElement`, он компилируется в JavaScript. В нём можно использовать выражения в `{}`, а атрибуты пишутся в camelCase.
2. **Чем props отличаются от состояния?** `props` передаются от родителя и доступны только для чтения. `state` — это внутренние данные компонента, которые он может изменять через `setState`.
3. **Почему изменение обычной переменной не заменяет useState?** Обычная переменная не вызывает перерисовку компонента. `useState` сообщает React, что данные изменились, и нужно обновить UI.
4. **Когда требуется функциональная форма обновления?** Когда новое состояние зависит от предыдущего (например, `setCount(prev => prev + 1)`).
5. **Почему нельзя менять объект задачи внутри поверхностной копии массива?** Если объект остался тем же, React может не заметить изменений или это приведёт к непредсказуемому поведению при сравнении ссылок.
6. **Для чего списку стабильный key?** Чтобы React мог правильно сопоставлять элементы при добавлении/удалении. Индекс использовать нельзя, так как при перестановке элементов состояние может сбиться.
7. **Почему видимая выборка и статистика не хранятся в отдельных состояниях?** Это производные данные. Их вычисление из `tasks` и `filters` на каждом рендере гарантирует синхронизацию и избавляет от ошибок.
8. **Как дочерний компонент сообщает родителю о действии?** Через вызов функций-колбэков, переданных в `props`.
9. **Что делает поле управляемым?** У него есть атрибут `value`, привязанный к состоянию, и обработчик `onChange`.
10. **Почему categoryId из select требует преобразования?** Значение `select` всегда приходит строкой, а в модели данных `categoryId` — число.
11. **Как меняется состояние формы при изменении её ключа?** При смене `key` React размонтирует старый компонент и создаёт новый, сбрасывая его локальное состояние.
12. **Почему подтверждение удаления не помещается внутрь функции обновления?** Внутри `setTasks` нельзя вызывать `window.confirm`, так как это побочный эффект (нарушение чистоты функции).
13. **Как отличить отсутствие задач от отсутствия совпадений?** В `TaskList` проверяется длина отфильтрованного массива. Если она 0, выводится соответствующее сообщение.
14. **Что проверяет npm test и чего он не проверяет?** Проверяет чистые функции (логику). Не проверяет React-компоненты и рендеринг.
15. **Какие части потребуется изменить для API в ПР8?** Заменить локальные функции изменения на `async` вызовы к API и добавить `useEffect` для загрузки.
